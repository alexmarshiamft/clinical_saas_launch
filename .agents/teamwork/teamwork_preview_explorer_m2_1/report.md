## 2. Technical Blueprint: `POST /api/create-checkout-session` in `server.ts`

### 2.1 Interface & Data Contracts

// Request Body Contract
interface CreateCheckoutSessionRequest {
  planId?: 'starter' | 'pro' | 'group' | string;

// Validation Error Contract (400 Bad Request)
interface CreateCheckoutSessionErrorResponse {
  error: string;          // "Invalid planId provided"

### 2.3 Input Validation & Defensive Handling
1. **Plan Identification**:
   - If `planId` is omitted (`undefined`) or empty string `""`: default to `"pro"`.
   - If `planId` is provided: must match a key in `VALID_PLANS` via `Object.prototype.hasOwnProperty.call(VALID_PLANS, planId)`.
   - If invalid string, numeric, object, or prototype key (e.g. `"toString"`, `"__proto__"`): reject with HTTP 400 and `{ error: "Invalid planId provided", validPlans: ["starter", "pro", "group"] }`.
2. **Billing Cycle**:
   - If `billingCycle === "annual"`, line item recurring interval is `'year'` and unit amount is annual amount (`selectedPlan.annualAmount`).
   - If omitted or `"monthly"`, recurring interval is `'month'` and unit amount is `selectedPlan.amount`.
3. **URL Resolution**:
   - Success URL: Default to `${APP_URL}/dashboard/subscription?status=success&session_id={CHECKOUT_SESSION_ID}&plan=${resolvedPlanId}`
   - Cancel URL: Default to `${APP_URL}/dashboard/subscription?status=canceled&plan=${resolvedPlanId}`
   - If client provides custom `successUrl` or `cancelUrl`, honor it.

### 2.4 Stripe SDK Integration (`sk_test_...`)
When `STRIPE_SECRET_KEY` is present and does not include `"placeholder"`:
1. Initialize Stripe SDK instance: `const stripe = new Stripe(stripeKey);`.
2. Call `stripe.checkout.sessions.create({ ... })` with:
   - `mode: 'subscription'`
   - `payment_method_types: ['card']`
   - `success_url: targetSuccessUrl`
   - `cancel_url: targetCancelUrl`
   - `line_items`: 1 item with `price_data` (currency `'usd'`, unit amount in cents, recurring interval `'year'` or `'month'`, product data).
   - `customer_email`: set if `clinicianEmail` is present.
   - `metadata`: `{ planId: resolvedPlanId, billingCycle: isAnnual ? 'annual' : 'monthly' }`.
3. Record session in memory registry (`sessionStore`) for fast retrieval by `GET /api/subscription/session/:sessionId`.
4. On Stripe API failure (e.g. invalid test key `sk_test_mock_nonexistent_key_audit_test`), catch error and return HTTP 502 with `{ error: "Failed to initialize Stripe checkout", details: stripeErr.raw || { message: stripeErr.message, error: { type: stripeErr.type || 'invalid_request_error' } } }`.

### 2.5 Resilient Sandbox / Demo Simulation Mode
When `STRIPE_SECRET_KEY` is unconfigured, or set to placeholder/sandbox:
1. Generate test session ID: `const simulatedSessionId = \`cs_test_simulated_\${uuidv4().replace(/-/g, "")}\`;`.
2. Generate checkout URL: `\${APP_URL}/dashboard/subscription?status=success&session_id=\${simulatedSessionId}&plan=\${resolvedPlanId}`.
3. Record simulated session in `sessionStore` with status `'complete'`, payment status `'paid'`, and active subscription flag.
4. Return HTTP 200 with `sessionId`, `url`, `simulated: true`, and plan metadata.

## 3. Technical Blueprint: `GET /api/subscription/session/:sessionId` in `server.ts`

### 3.1 Purpose & Role in Architecture
When a clinician completes checkout or tests a subscription redirect, the browser is sent to `/dashboard/subscription?status=success&session_id={CHECKOUT_SESSION_ID}&plan={planId}`.
The frontend or audit script queries `GET /api/subscription/session/:sessionId` to:
1. Verify that the session completed successfully and payment is confirmed.
2. Retrieve the active tier (`starter`, `pro`, `group`) and renewal parameters.
3. Activate `<SubscriptionGate>` permissions for the authenticated clinician.

### 3.2 Endpoint Specification

- **Path**: `GET /api/subscription/session/:sessionId`
- **Path Parameters**: `sessionId` (String)

#### Response Contracts:
**Success (200 OK):**
```json
{
  "sessionId": "cs_test_simulated_9d1f3b...",
  "status": "complete",
  "paymentStatus": "paid",
  "subscriptionStatus": "active",
  "tier": "pro",
  "planName": "Clinician Pro",
  "billingCycle": "monthly",
  "customerEmail": "sarah.chen.md@behavioralhealth.org",
  "isSubscribed": true,
  "simulated": true,
  "createdAt": "2026-10-05T01:50:00.000Z"
}
```

**Missing/Invalid Parameter (400 Bad Request):**
```json
{
  "error": "sessionId parameter is required"
}
```

**Nonexistent Session (404 Not Found):**
```json
{
  "error": "Checkout session not found",
  "sessionId": "cs_unknown_session_123"
}
```

 * Milestone 2 Acceptance Criterion AC3 & Requirements §R2

 * 1. POST /api/create-checkout-session handles plan tiers ('starter', 'pro', 'group')

  });

  let ready = false;
  serverChild.stdout.on('data', (data) => {
    if (data.toString().includes(`running on http://localhost:${TEST_PORT}`)) {
      ready = true;
    }
  });

  // Wait up to 10 seconds for server startup
  const start = Date.now();
  while (!ready && Date.now() - start < 10000) {
    await new Promise((r) => setTimeout(r, 100));
    if (serverChild.exitCode !== null) {
      throw new Error(`Server exited prematurely with code ${serverChild.exitCode}`);
    }
  }

  if (!ready) {
    throw new Error('Timed out waiting for test server to initialize');
  }

  console.log(`✓ Ephemeral server online at ${BASE_URL}\n`);
  return BASE_URL;
}

function cleanup() {
  if (serverChild && !serverChild.killed) {
    try {
      serverChild.kill('SIGTERM');
    } catch {}
  }
}

process.on('exit', cleanup);
process.on('SIGINT', () => { cleanup(); process.exit(1); });
process.on('SIGTERM', () => { cleanup(); process.exit(1); });
